# Section 5.3 Sensitivity Analysis

This directory contains the Section 5.3 sensitivity outputs generated by `tools/run_5_3_sensitivity.py`.

The experiment uses the final algorithm setting, `BD-P-NR`, through `METHOD = "BD-P-NR"` in `tools/section5_2_common.py`. Each case solves a `stochastic_row` design and then evaluates the saved ROW schedule.

Current formal run:

- Instance: `Sioux_Falls_30OD_Y1_S10_H1_M10`.
- Scenario set: `S10`.
- Cases: 10 total.
- Budget cases: `0.15`, `0.25`, `0.35`, `0.45` of total candidate ROW resource.
- Background traffic cases: `0.5`, `1.5`, `2.0`.
- Demand cases: `0.5`, `1.5`, `2.0`.

The reported scope is intentionally limited to `Y1/S10`. Results for `Y3/S10`
and `Y5/S10` were not run and are not included. All 10 completed design solves
reached the 7200-second limit; their total elapsed time was 20.63 hours. The
saved incumbents, bounds, gaps, and statuses are therefore reported as the
completed sensitivity evidence rather than presented as proven optima.

Each budget value is a fraction of the total resource weight of all candidate
ROW cells, not a fraction of the baseline budget or of the incumbent design.

The command for this reported scope is:

```powershell
cd C:\faq_work\Papers\ROW\ROW-Design
conda run -n row-design-cplex221 python tools\run_5_3_sensitivity.py
```

`aggregate.csv` is the main summary table. It includes objective values, component costs, ROW usage metrics, `design_gap`, `design_status`, and elapsed time for each sensitivity case.

## Data Notes

`aggregate.csv` has 10 rows: 4 budget cases, 3 background traffic cases, and 3 demand cases. All cases currently have `design_status=time_limit`; the final gaps are recorded in `design_gap` and match the corresponding `gap` values in each case's `design_summary.json`. Each case directory includes `design_summary.json`, `evaluation.json`, `scenario_reports.json`, `expected_link_metrics.csv`, `scenario_link_metrics.csv`, `scenario_arc_period_metrics.csv`, `row_schedule.csv`, `row_schedule_incumbent.csv`, `progress.csv`, and `progress.json`.
