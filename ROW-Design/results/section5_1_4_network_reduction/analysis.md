# Section 5.1.4 Network Reduction Analysis

The current 5.1.4 results cover the required Y1/S10 instances:
R04-R10 and Sioux_Falls_30OD, with both unreduced and R1-R3 reduced
networks. The table is generated by
`tools/run_5_1_4_network_reduction.py`.

The reductions are substantial for every benchmark.  Across the eight
instances, time-space node counts fall by 59.74%-78.67%, total
time-space arc counts fall by 74.30%-84.68%, and the deterministic-
equivalent variable-count proxy falls by the same order of magnitude.

The runtime comparison supports the value of preprocessing.  The reduced
network is faster on every instance, with an average speedup of 2.85x.
The clearest gains occur on R04, R07, R08, and R09, where speedups range
from 3.22x to 4.77x.  R06 improves from a time-limited unreduced run to
a converged reduced run.  The hardest cases, R05, R10, and
Sioux_Falls_30OD, still hit the time limit after reduction, but the final
optimality gaps improve.

Under the current implementation, the effective marginal reduction is
driven by the R1 shortest-time screen.  R2 reachability and R3 budget-path
screening have no additional marginal effect after R1 on these Y1/S10
instances.  This is a property of the current benchmark data and
implementation order, not a general theoretical claim about the rules.
